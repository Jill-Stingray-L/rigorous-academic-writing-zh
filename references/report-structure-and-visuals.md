# 研究报告结构与图表

本参考适用于理论研究报告、项目研究报告、技术分析报告和咨询研究报告。报告可以面向决策者，但结论仍应能追溯到材料和方法。

## 一、报告主线

报告不是材料目录或概念汇编。建议先形成一条可复述的主线：

`现实问题 → 研究目标与问题 → 理论方法 → 数据或材料基础 → 分析 → 结果 → 模型或方案 → 实施含义`

摘要、第一章和结论使用同一组研究问题。中间各章分别提供答案，结论按原顺序收束。背景、目标和问题分开写：背景解释为何研究，目标说明要形成什么认识或成果，问题规定需要回答的具体事项。

## 二、章节接口

每章开头交代本章使用哪些前序结果、解决什么问题。每章结尾概括本章形成的对象、指标、模型或判断，并说明它如何成为下一章的输入。接口句应包含实际名词，避免“承上启下”“在前文基础上进一步分析”等空壳表述。

理论章节只讲原理、机制、结构、步骤和本研究的使用策略。分析章节将方法落到实际系统、样本、表、字段、文献、访谈或问题记录。控制模型或方案章节说明“为什么需要、由什么构成、如何建立、如何使用”，并明确哪些是设计结果、哪些已经运行。

结果性段落先给出材料记录、统计或模型输出，解释性段落再说明可能原因、业务含义和适用边界。两类内容位于同一小节时，用明确的证据动词和段落功能区分。

## 三、小标题和段落

小标题下不能只有图、表、一句话或定义。重要小节通常需要多个连贯段落，分别完成背景或对象界定、分析过程、结果解释和本节作用。段落长短由信息决定，避免每节机械复制同一种结构。

标题应准确命名本节实际内容，避免“战略对齐、价值赋能、体系升级”等宣传化标题。首次出现的对象、指标、分组、符号和模型应先解释，再给出统计或图表。

## 四、图、表和正文的选择

### 使用正文

适合两三项结论、少量数字、概念解释、因果或逻辑说明。能用连续文字清楚表达的内容，不为增加形式而制表。

### 使用表格

适合多对象多属性的精确比较、分类规则、指标定义、系统—数据映射、分阶段任务或需要逐项查找的结果。表格中避免塞入整段论述；关键解释回到正文。

### 使用图形

适合流程、层级、网络、时间顺序、趋势、分布、空间关系和模型构件。图形应让关系比文字更清楚。单纯把文字放进彩色框，通常不能增加分析信息。

## 五、图表说明的最低内容

正文在图表前后完成以下任务，信息简单时可以合并，复杂模型应分别展开：

1. 为什么需要这张图或表；
2. 读者应如何读取维度、节点、方向、颜色或分组；
3. 哪些数值、结构或差异最重要；
4. 这些结果如何支持本节判断或下一步分析。

不要只写“图 3-1 展示了系统分布情况”。应补充主要分布、差异及其意义。正文也不应逐格复述表格。

## 六、图表制作与排版

- 图题和表题使用统一编号，并由排版系统放在规定位置；图内不重复图题。
- 图中字体、线宽、箭头、颜色、节点间距和图例保持一致，缩放到最终页面后仍能辨认。
- 颜色之外再使用形状、线型或文字编码，保证灰度打印和色觉差异下可读。
- 图表中的数字、术语、单位和正文一致。正文引用编号与实际编号一致。
- 表格文字不继承正文首行缩进；数值小数位、单位和对齐方式统一。
- 图表附近不放“注：”“来源：”“待完善”等制作提示，除非目标规范明确要求正式图注或来源项。

## 七、贯穿案例

案例首次出现时完整定义。后续章节直接使用稳定名称，只补充本章新增的质量传播、血缘、控制或实施信息。跨章重复同一段系统—表—字段链条，会削弱研究推进感。

## 八、交付前检查

- 所有图表都在正文中被引用；
- 所有图表都有足够的文字解释；
- 每个小标题下有实际分析内容；
- 表格用于比较而非替代叙述；
- 图形表达的结构与正文模型定义一致；
- 附件或底稿清单与正文成果边界清楚；
- 正文没有编辑提示、聊天残留和未完成标记；
- 结果与解释边界清楚，结构适用性没有写成运行成效；
- 引用在改写后仍靠近并只支持原命题；
- 格式模板在内容和图表稳定后统一应用。
